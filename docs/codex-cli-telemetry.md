# Codex CLI telemetry configuration

Threadforge provides an explicit, user-level configuration installer for Codex CLI. It adds a managed TOML block to `config.toml` under `$CODEX_HOME` (default `~/.codex`) and points OTLP/HTTP logs and traces at the loopback Threadforge service on port `4318`. The exported `installCodexTelemetry({ codexHome?, endpoint? })` function accepts an optional loopback HTTP origin for isolated local deployments and tests; remote origins, paths, credentials, queries, and fragments are rejected. The CLI installer continues to use the default `127.0.0.1:4318` origin.

```powershell
npm.cmd --prefix adapters run adapter -- telemetry install --host codex-cli
npm.cmd --prefix adapters run adapter -- telemetry update --host codex-cli
npm.cmd --prefix adapters run adapter -- telemetry uninstall --host codex-cli
```

Set `CODEX_HOME` before running those commands to select a different Codex user home. Start `threadforge serve` before expecting telemetry to be accepted. The installer does not start the service, configure forwarding, copy authentication, or modify `auth.json`.

The managed block sets `otel.environment = "local"`, disables metrics export with `otel.metrics_exporter = "none"`, disables user-prompt logging with `otel.log_user_prompt = false`, and configures separate JSON OTLP/HTTP endpoints for logs and traces. This is an opt-in host configuration change; telemetry may contain information beyond the prompt field, including tool/session details. Captured records are stored in Threadforge's local stores. Protect the Codex home and Threadforge data directory accordingly; this installer does not promise that all telemetry fields are content-free.

Configuration edits are deliberately conservative. The installer refuses to proceed if `config.toml` already has an unmanaged `otel` table or key, if the Threadforge-owned block's hash no longer matches, or if the file is malformed in a way that makes ownership ambiguous. It preserves unrelated bytes and line endings, uses a local lock and atomic replacement, rejects symlinked/non-regular config files, and caps input at 8 MiB. Update and uninstall only replace/remove a block whose content still matches its ownership hash. A newly created `config.toml` is removed on uninstall only when it contains nothing else.

On October 15, 2026, the installed-host smoke ran Codex CLI `0.162.1` with an isolated `CODEX_HOME`, deterministic loopback Responses provider, and ephemeral loopback OTLP collector. The completed repository gate observed one JSON log batch (26 records) and two trace batches (699 spans); its separate local turn-cost request was counted but not retained. The fixture detected no user-prompt text or API-key marker. The approved procedure guidance did appear in the locally received telemetry, so this is not content-free capture: enable this integration only when local trace retention is acceptable, and keep remote forwarding disabled unless separately reviewed and explicitly enabled. No real model or customer collector was contacted. This verifies only the pinned CLI/config path and fixture behavior, not other Codex versions, settings precedence/trust, real-provider behavior, or token-attribution reconciliation. See OpenAI's [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference) for host configuration and precedence. The CI-local Codex configuration is separate and uses an isolated temporary `CODEX_HOME`; see [CI capture](ci.md#capture-codex-cli).
