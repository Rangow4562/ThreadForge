# Session handoff

Threadforge can discover sessions in the 14 local native stores documented by Beacon and export a bounded handoff brief from either a native store or its private local event log:

```powershell
threadforge handoff list [--harness <runtime>] [--here|--dir <absolute-workspace>] [--subagents] [--limit 25] [--json]
threadforge handoff list --store-dir <runtime>=<absolute-path> [--store-dir <runtime>=<absolute-path> ...]
threadforge handoff export <session-id> [--source runtime-log|native] [--harness <name>] [--traces <events.jsonl>] [--store-dir <runtime>=<absolute-path>] [--output-dir <private-dir>] [--print|--json]
threadforge handoff resume <session-id> --harness <runtime> [--source native|runtime-log] [--agent <runtime>] [--cwd <directory>] [--new] [--print [--json]|--yes]
```

`list` reads Claude Code, Codex CLI, OpenCode, Cline, Pi, Prime Agent, Factory Droid, GitHub Copilot CLI, Hermes Agent, DeepSeek Harness, fx, Grok Build, OpenClaw Gateway, and Cursor stores. Reads are local and read-only. A store failure does not hide sessions from other runtimes; text mode prints a path-free warning, and JSON reports a path-free warning code by harness. A bounded partial scan uses warning code `scan_truncated`. Shared native-reader limits are 10,000 directory entries per store and per directory, depth 24 for recursive readers, 1 MiB per metadata file, and 64 MiB aggregate metadata per store; Cline history files use a 25 MiB per-file ceiling under the same aggregate budget. DSH metadata decompression is capped at 1 MiB compressed and expanded; OpenCode and Hermes SQLite listing refuses databases over 512 MiB and bounds listed text fields. The default result limit is 25; `--limit 0` returns all discovered entries up to 10,000. This response cap remains distinct from each reader's I/O budget. `--here` and `--dir` filter by workspace. `--store-dir` is repeatable and accepts the runtime-specific location documented by Beacon; the dedicated Claude/Codex/OpenCode/Cline flags are aliases. JSON output uses `threadforge.native-session-list.v1`; it includes native IDs and local source paths, so treat it as private local data.

IDs for `export` may be exact or a unique prefix of at least six characters. If the same ID exists under more than one harness, pass `--harness`. The default `--source` is `runtime-log`, preserving the lower-fidelity Threadforge `traces/events.jsonl` behavior; `--traces` must be an absolute local path. `--source native` reads the selected harness's local session store and requires `--harness`; repeat `--store-dir runtime=<absolute-path>` to override that store. Native reads cap aggregate source bytes at 64 MiB, mapped events at 10,000, and DSH expanded transcript data at 128 MiB. Oversized, unsafe, or unavailable sessions fail without creating a brief. The bridge drops raw native record maps before events reach the brief builder.

By default, the brief is written beneath `<THREADFORGE_HOME>/handoffs` (or the platform cache's `threadforge/handoffs` directory). A custom `--output-dir` must be an absolute local path. New handoff directories are private (`0700` where supported), files are created with private permissions (`0600` where supported), and existing files are never replaced. Names use a hash of the harness/session identity instead of putting the native session ID or workspace path in the filename.

The Markdown is capped at 48 KiB and prefers the latest activity. It includes up to 30 recent entries, at most 1,200 runes per activity body, 800 runes for first/latest requests, 12 recent commands, and 40 changed paths. Older trace rows outside the 64 MiB scan window and native events beyond the read cap are disclosed. Content is sanitized again before rendering; assistant reasoning, tool arguments, raw event maps, and credentials are excluded or redacted. `--json` writes the brief and returns a content-free `threadforge.handoff-export.v1` receipt with the brief digest and scan warnings. `--print` is the only mode that writes brief content to stdout; it creates no file.

`resume` defaults to `--source native`; select the source with `--harness` and optional repeated `--store-dir runtime=<absolute-path>`. Use `--source runtime-log` to select a Threadforge-captured session instead; `--traces` may override its local JSONL path. `--agent` defaults to the source runtime. A native session is reopened only when the selected reader provides a compatible native reference, the reference still exists, the runtime supports reopening that session kind, and any working-directory constraint is satisfied. Otherwise, or with `--new`, Threadforge plans a new interactive session from a private brief. The plan is `threadforge.handoff-resume-plan.v1` in [`handoff-resume-plan-v1.schema.json`](../schema/handoff-resume-plan-v1.schema.json).

`--print` shows the plan without creating a brief or starting a process; `--json` requires `--print` and returns the same versioned plan. Without `--print`, Threadforge prints the plan and asks `Continue? [y/N]`; a non-terminal invocation fails closed unless `--yes` is supplied. The brief is written privately only after confirmation, then the target CLI is launched directly with an argument vector (no shell). Approval-sensitive targets receive explicit safe modes or environment overrides, including Cline `--auto-approve false`, Grok `--permission-mode default`, and clearing Copilot/Hermes auto-approval switches. The target receives a path to the brief, not its contents in the process arguments. Its first prompt asks it to read the brief as stale/untrusted context, inspect the current tree, restate the task, and wait for confirmation; a bounded Beacon-compatible handoff marker is appended when the source ID can be represented. The marker is an unverified claim, not execution authorization.

The implemented new-session targets are Claude Code, Codex CLI, OpenCode, Cline, Pi, Prime Agent, Factory Droid, Copilot CLI, Grok Build, OpenClaw, Cursor, Oh My Pi, Gemini CLI, Qwen Code, Kiro, Antigravity CLI, Devin CLI, Muse Code, OpenHands, and Goose. Hermes and fx can reopen supported native sessions but do not start a new session from a brief; DeepSeek Harness cannot be started by this command. Cursor native reopen is available only for a top-level CLI transcript whose regular, non-symlink `chats/<workspace-md5>/<session-id>/store.db` exists under `CURSOR_CONFIG_DIR`, `$XDG_CONFIG_HOME/cursor`, or `~/.cursor`; Composer-only sessions, subagents, missing stores, and a different `--cwd` fall back to a new brief-based session. Threadforge prefers the current `agent --resume <session-id>` executable and falls back to the legacy `cursor-agent` name. See [Cursor CLI](https://cursor.com/docs/cli/using). These argument plans have fixture coverage, not live-version compatibility evidence; cross-harness task-success and event-link acceptance remain open.

A brief is stale-able guidance, not a source of execution authority. Review the current working tree and confirm the task before changing files. Threadforge creates a bounded marker for brief-based continuations. The 14 vendored native readers and TypeScript live collectors for Claude, DeepSeek, Devin CLI/Desktop, Grok, Hermes, OpenHands, Kiro, Muse, Kimi Code, Qwen Code, Cline, OpenCode, Oh My Pi, Senpi, and Codex rollout polling can map that marker to a separate `session.handoff` event when the destination session ID is present. TypeScript adapters retain only the parsed marker claim in process memory; prompt and marker text are not added to the event. Intake and trace batches are capped at 200 events to allow 100 prompt/link pairs. The source claim is unverified, not proof that the source session is genuine. Fixture-tested mapping, planning, and confirmation are implemented, but live runtime compatibility, cross-harness task-success, and end-to-end event-link acceptance remain incomplete. See the [feature parity ledger](feature-parity.md#beacon-session-handoff).
