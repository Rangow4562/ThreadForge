# Installed skill, Qoder command, Command Code, and MCP dispatch smoke

Smoke v29 adds an isolated Codex task-plan-gate probe with a persisted synthetic plan_only task. Codex CLI 0.163.0 exposed exec_command but not direct apply_patch in the fixture request. The probe scripted one exec_command that would create a sentinel; the PreToolUse denial returned to the fixture and the file remained absent. The subresult is verified with one tool call and zero real model invocations. This is deterministic transport evidence, not a security-boundary claim, and it does not test governed-execution shell path scope, normal trust discovery, or MCP writes.

Run the no-model host check from `adapters/`:

```powershell
npm run test:installed-skills
```

The smoke requires the Go toolchain and its module dependencies already cached (`GOPROXY=off`), Node.js 22.6 or later, and OpenCode, Gemini CLI, Codex CLI, Claude Code, Command Code, and Antigravity CLI installed. GitHub Copilot CLI is checked when available and otherwise reports `not-installed`.

The script builds the Threadforge CLI with `GOPROXY=off` and uses the OpenCode adapter on two payload-shaped fixtures. It verifies that mapped events contain no prompt, path, session ID, or tool-call ID, then drives a deterministic draft through `procedure propose`, fixture-only `record-validation`, human `approve`, and `export-skill` in a disposable SQLite store. The same exported bytes and SHA-256 are passed through the Claude Code, Cline, GitHub Copilot, Codex CLI, Cursor, Gemini CLI, Antigravity, OpenCode, ZCode, DeepSeek Harness, and Qoder CLI project-skill installers. It verifies each target path, byte-for-byte and digest equality, shared `.agents/skills/` ownership behavior, DeepSeek's separate `.dsh/skills/` ownership, Qoder's separate `.qoder/skills/` ownership, preservation of a neighboring user-owned skill, and preservation of Copilot's `.github/copilot-instructions.md`. It also installs a separately rendered Qoder slash command, verifies its output digest and advisory body, and preserves an adjacent user command and `AGENTS.md`. OpenCode's installed CLI is given a project-local Threadforge MCP entry, must report it connected via `opencode mcp list --pure`, and runs an isolated agent turn against a deterministic loopback OpenAI-compatible fixture provider. Codex CLI gets the project-scoped `.codex/config.toml` MCP entry; the smoke trusts only the disposable project through a temporary `CODEX_HOME`, uses a local fixture Responses provider, and runs `codex exec --ephemeral --sandbox read-only`. Antigravity CLI gets an isolated `.agents/mcp_config.json` entry and runs a headless project MCP read against a local Gemini-API-shaped fixture provider. Each provider scripts exactly one `threadforge_procedure_get` call and checks that the approved fixture guidance appears in the MCP result and final output. These checks verify installed-host dispatch/result transport without real model inference. Claude Code receives an explicit temporary project settings file and isolated `CLAUDE_CONFIG_DIR`; the smoke publishes and freshness-checks a source-bound v2 project fact, installs the `UserPromptSubmit` hook, then runs `claude --print` passing `--tools ""` as a request to disable built-in tools, with session persistence disabled and `ANTHROPIC_BASE_URL` set to a loopback-only deterministic Messages fixture. On Claude Code `2.1.303`, the request still included built-in tool definitions; the fixture returned text only and the smoke observed no tool-use/result blocks. This does not prove host permission enforcement. The hook's approved fact must appear in every model-bound request and in the fixture response. Only the observed local `/api/hello` health probe and Messages API routes are accepted. This verifies hook invocation and context transport for the installed CLI version, not normal project-settings discovery/trust, model selection, or task success. Skill discovery is checked with OpenCode `debug skill --pure`, Gemini `skills list` when that local command is available without auth, and Codex `debug prompt-input`; no ZCode, DeepSeek Harness, or Qoder CLI discovery/model-use claim is made. If Gemini requires authentication even for local inventory, the smoke reports an explicit skip in the isolated home instead of borrowing user credentials or calling a model.

The proposal content, validation report, provider tool calls, and final guidance responses are deterministic fixtures—not model output or held-out acceptance evidence. OpenCode, Codex CLI, Antigravity, and GitHub Copilot CLI run isolated sessions and dispatch read-only MCP calls (OpenCode performs one procedure read and one task-resume read); Command Code's agent run may be explicitly skipped if its isolated CLI requires login. No real model is invoked, no actual host history/session data is read, and no real project traces are used. The fixture's scripted calls do not establish that a model would choose, interpret, or follow retrieved memory on a real task.
