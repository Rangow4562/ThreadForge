# Dependency and license audit status

Status: **open; not legal clearance for redistribution.** This workpaper records the repository inventory checked on **November 5, 2026**. It separates machine-readable lock metadata from actual license review; a package's declared license field or a successful build does not by itself establish compatibility.

The fresh `scripts/generate_dependency_inventory.py --repo-root .` inventory on November 5, 2026 contains 931 components across 10 manifests. Its 477 `missing_declared_license_metadata` entries mean **license metadata was not collected**, not that those components are unlicensed. Inventory v3 breaks the missing declarations down as 77 Go module records and 400 Python package records; it does not infer licenses. It reports 0 `unresolved_versions`: the 277 external `python/uv.lock` package records have resolved versions and artifact hashes, while the 32 direct source requirements are retained on their locked records with pyproject manifest hashes. All 454 npm lock entries have a nonempty declared license field, including the new pinned `yaml` parser dependency used by Aider's explicit project-config adapter. Every inventory entry still has `license_review_status=unreviewed`, and `release_clearance=false`.

Uncollected license metadata by source manifest: `containers/engineering/build-requirements.lock` (pypi): 3, `containers/engineering/requirements-linux-x86_64-py312.lock` (pypi): 120, `go.mod` (golang): 77, `python/uv.lock` (pypi): 277.

## Repeatable dependency inventory

Run `python scripts/generate_dependency_inventory.py --repo-root .` to print the inventory, or add `--output <new-file>` to write a JSON file. The versioned `threadforge.dependency-inventory.v3` contract records hashes for its input manifests and components from the resolved Go module graph, both npm lockfiles, the Engineering runtime/build Python locks, and every external package/version record in `python/uv.lock`. Python lock resolution markers and package artifact hashes are retained; direct pyproject requirements are attached to their resolved package records. Registry URLs and machine-local paths are omitted. v3 adds deterministic missing-license-metadata counts by ecosystem and source manifest without inferring licenses. The v1 and v2 schemas remain available for earlier inventory payloads.

The report marks every component `license_review_status=unreviewed`; missing license metadata stays missing, automatic license inference is false, and `release_clearance` is always false. The direct pyproject ranges remain flexible for unlocked installs, while inventory v3 records the exact locked versions used by CI. This is still not a complete release-artifact SBOM, license classification, or legal approval. `test.ps1` generates it only under a unique temporary path.

Release-candidate builds add separate per-target Go license-evidence archives using pinned `go-licenses` v2.0.1 against `./cmd/threadforge` with the candidate's `GOOS`/`GOARCH`. The collector saves the scanner's report and notice files with source-commit, scanner-binary, and per-file hashes; it fails on an unknown license expression, records missing source URLs and native-code inspection warnings, and always sets `license_review_status=unreviewed` and `release_clearance=false`. The [scanner project's README](https://github.com/google/go-licenses) states it is not an officially supported Google product; its result is machine-collected evidence, not Google endorsement or legal review.

The release-candidate workflow also collects Python license evidence from six locked environments: Linux, Windows, and macOS on Python 3.11 and 3.12, each with the `test`, `decisions`, and `workspace` extras. `scripts/build_python_license_evidence.py` records the source commit, candidate version, platform/runtime, selected extras, `uv.lock`/`pyproject.toml` hashes, installed package metadata hashes, safe license-expression/classifier fields, and hashes plus copies of discovered license/notice files. The collector source hash normalizes CRLF to LF so its identity is consistent across Windows and Unix checkouts. It rejects installed distributions absent from the lock and unsafe/oversized paths or payloads. Missing metadata/files stay explicitly missing; it does not infer a license. Each deterministic archive is provenance-attested and included in the combined candidate checksums. The collector remains `license_review_status=unreviewed`, `license_review_required=true`, and `release_clearance=false`.

This Python evidence is a readback of only those six installed environments; it does **not** populate the lockfile inventory's missing Python metadata entries, establish the license of a package from its notice text, or cover the `hf`, `serving`, `typed-data`, or `evolution` extras, the Engineering container/runtime, or benchmark datasets/evaluators. In particular, successful lock resolution is not evidence that the `serving` extra's Linux/Python 3.11 `vllm` installation or runtime works. Neither the Go nor Python collectors review compatibility or grant legal approval.
