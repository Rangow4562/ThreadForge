# Public release status

Status checked **November 6, 2026**: GitHub's latest public stable release is `v0.5.0`, published November 5, 2026 from tag and `main` commit `1254e70b8a0204f3e4bcd3e8c44afdce8e2a67ec`. The main push and tag release-candidate workflows (runs `42046749005` and `42046799559`) subsequently passed all seven test/ingestion jobs, six Python evidence jobs, four target builds, and candidate assembly.

Threadforge has **not** passed the all-or-nothing production/cutover acceptance gate. Publishing `v0.5.0` is not evidence that Beacon, Mancode, AnyJev, or RRSI can be retired or replaced. Do not use this release as authorization to cut over or delete legacy data.

The public `v0.5.0` release page contains four CLI archives and `checksums.txt`. All four downloaded files match those checksums, but all four public asset SHA-256 digests differ from the corresponding attested candidate files; `gh attestation verify` returns HTTP 404 for each public digest, while verification succeeds for the corresponding candidate Linux archive. The release page contains no standalone SPDX or Go/Python license-evidence assets. Archive inspection found that the three Unix archives contain only `threadforge`; the Windows ZIP contains `threadforge.exe`, `LICENSE`, and `NOTICE`, but not `THIRD_PARTY.md` or the target-specific Go license bundle. Thus the public assets are not the files produced by the successful attested candidate workflow and do not carry the complete legal payload required by the release process. Keep `v0.5.0` available only as an unapproved release until an authorized correction; this repository update does not alter or replace it.

New version tags run the release-candidate jobs only after all twelve OS/Python suites and the Elasticsearch synthetic-ingestion job pass. The workflow builds four supported CLI archives, produces an SPDX SBOM and target-specific Go license evidence per binary, collects twelve Python evidence bundles, and assembles 24 checksummed payloads into a temporary Actions artifact with provenance attestations. The workflow does not create or modify a public GitHub Release. Publication must attach the exact verified candidate files without rebuilding or recompressing them. See the [release-candidate process](release-process.md).
