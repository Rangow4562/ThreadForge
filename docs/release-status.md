# Public release status

Status checked **November 5, 2026**: GitHub's latest public stable release is `v0.4.6`, published October 30 from tag commit `a5b9e73436876038fb7d3e40268eece298af4c7b`. The current `main` source has advanced beyond that tag; installers that select the latest release install the `v0.4.6` binary, not current `main`.

GitHub marks `v0.4.6` as a stable release, but Threadforge has **not** passed the all-or-nothing production/cutover acceptance gate. Its publication is not evidence that Beacon, Mancode, AnyJev, or RRSI can be retired or replaced. Do not use this release as authorization to cut over or delete legacy data.

The `v0.4.6` release includes `checksums.txt`, but that checksum was published alongside the archives and is not a publisher signature or independent build-provenance attestation. The existing `v0.4.6` assets have not been retroactively attested. New version tags now run the release-candidate job in the main test workflow only after all six OS/Python suites and the Elasticsearch synthetic-ingestion job pass. That job builds the four supported CLI archives with the tag version embedded, generates an SPDX SBOM for each binary, reconciles its module inventory with that binary's embedded Go build information, creates build-provenance attestations for each archive and SBOM file, binds each archive to its SBOM with a separate SBOM attestation, and attests the combined checksum file. It uploads a 14-day workflow artifact and deliberately does not create or modify a public GitHub Release. See the [release-candidate process](release-process.md).

Verified November 5, 2026: non-publishing rehearsal run `41996565159` built version `0.4.7` from commit `321d747` after all six OS/Python suites and Elasticsearch ingestion passed. The downloaded bundle contained four archives, four SPDX files, and `checksums.txt`; all eight hashes matched. `gh attestation verify` independently accepted SLSA provenance for every archive, every SBOM, and the checksum file, plus each archive's SPDX predicate. The first attempt encountered an HTTP 504 while Syft downloaded its checksum list; rerunning the failed job succeeded. The workflow now retries SBOM generation once and remains fail-closed on a repeated error. This rehearsal did not create or alter a public release.

Verified November 5, 2026: rehearsal run `42005641367` passed all seven required test/ingestion jobs and built all four version `0.4.7` targets from commit `6b51821`. The new binary-to-SBOM reconciliation step passed on Linux amd64, macOS amd64/arm64, and Windows amd64. The nine-file candidate bundle's eight checksums matched; archive contents were exactly one intended CLI binary each. All 13 attestations verified against the repository, artifact digest, workflow, and source commit (nine SLSA provenance and four SPDX archive-to-SBOM claims). The SBOMs still contain unasserted license fields, so this closes package-coverage reconciliation only—not license review, full runtime SBOM coverage, or release clearance. No public release was created or changed; `v0.4.6` remains latest.

The remaining release gates are tracked in the [cutover assessment](cutover.md), [feature-parity matrix](feature-parity.md), and [license audit](license-audit.md). They include complete documented feature and host parity; authoritative populated-source migration, reconciliation, and rollback; independent trusted held-out efficacy results; release-artifact SBOM and license/privacy/security/name approvals; and a rollback rehearsal with explicit cutover approval. The dependency inventory still reports `release_clearance=false`.

The candidate-build workflow proves how its own files were built; it is not a passing cutover assessment or license/privacy/security/name approval. Do not publish a replacement release or retire legacy systems until the cutover assessor accepts the full evidence set and required approvals are recorded.
