# Threadforge Python modules

For a reproducible local test environment, run `uv sync --project python --locked --extra test --extra decisions --extra workspace` from the repository root, then run checks through `uv run --project python --locked --extra test --extra decisions --extra workspace ...`. `python/uv.lock` resolves every optional extra and platform marker; the standard CI matrix installs and exercises only `test`, `decisions`, and `workspace`. The `hf`, `serving`, `typed-data`, and `evolution` extras are lock-resolved but are not all runtime-validated by that matrix. The lock pins dependency artifacts; it does not establish license approval or API compatibility for extras that are not tested.

The versioned operation `decision.model.truncate` converts an existing local HF checkpoint into a new depth-truncated checkpoint. It requires a new output directory, never downloads or overwrites, strips source-path metadata, and returns hashes/counts with review-required, execution-unverified, cutover-ineligible status. Its optional `dtype` is `auto` by default; use explicit `float16`, `bfloat16`, or `float32` only when changing checkpoint precision is intended.

The optional `hf` extra supports the Transformers 4.x `torch_dtype` API and the Transformers 5.x `dtype` and causal-mask signature changes. Compatibility tests simulate both API shapes; no authentic Transformers 5 checkpoint has been loaded in the current verification environment.

`threadforge decision benchmark pipeline --file <serving-pipeline-request.json>` / `decision.serve.pipeline` runs a local AnyJev-style depth, fit, accuracy, ECE, and latency benchmark using a fingerprinted checkpoint and caller-supplied versioned train/test cases. Each depth uses a fresh ephemeral `--api-key`; the runner requires authenticated `/v1/models` readiness before sending cases and binds vLLM only to `127.0.0.1` (API-key auth does not protect every vLLM route). It supports Linux/WSL process-group cleanup and always marks caller-held-out provenance and cutover eligibility false. Install the optional runtime with `python -m pip install -e ".[serving,hf]"`; request/result contracts are in `schema/anyjev-serving-pipeline-{request,result}-v1.schema.json`.

The vendored AnyJev decision/calibration library and RRSI selection primitives are exposed through `threadforge.python.v1` JSON-lines messages. The Python process has no SQLite dependency or store access. Its default model path is local-only; an external vLLM endpoint requires `remote_opt_in: true`, and a non-loopback endpoint additionally requires HTTPS.

`decision.calibrate` accepts optional `fit_options` only for L2 calibration and forwards them to AnyJev `Decider.fit_head`. Defaults are `layers=null`, `kinds=["lda", "ridge"]`, `n_folds=5`, `seed=0`, and `listing="auto"`; bounds and allowed values are validated before backend construction. Its versioned result marks the artifact review-required and never authorizes activation or execution.

Install the base package and optional local inference dependencies with `python -m pip install -e ".[decisions,hf,test]"`. For the Harvey workspace adapter or Engineering MCP gateway, install `python -m pip install ".[workspace]"`; this includes FastMCP, Uvicorn, the workspace runner assets, and the pinned Apache-licensed Archipelago runtime including the Engineering harness. The workspace adapter first uses runtime assets in a candidate source tree, then falls back to those packaged assets. The Engineering `Domain.run()` path now orchestrates an explicitly opted-in task through isolated agent execution, task MCP/model brokering, and a separate canonical evaluator; its smoke path uses the same one-trial flow. This is implemented and mocked-test-covered, but requires a verified digest-pinned image and live Docker/FastMCP/model/evaluator validation before its results can count as benchmark acceptance. Run the protocol adapter with `python -m threadforge_py`; each input line receives one JSON response line on stdout, and diagnostics never go to stdout.

`python scripts/verify_distribution.py` builds the source archive and its wheel in a temporary copy using the installed PEP 517 backend with `--no-isolation`. The `test` extra includes `pip>=24,<27`, `setuptools>=77`, and `wheel`; the verifier checks these are available before building and installs the wheel into a temporary target. It verifies the required workspace/Engineering assets and upstream notices, rejects bundled model or benchmark binary payloads, and exercises `python -m threadforge_py` with the local capabilities operation. The check performs no model inference and leaves no build products in the repository.

Operations currently include capabilities discovery, typed-question validation, single-state decisions, bounded multi-state/single-question decisions through AnyJev `Decider.decide_batch`, approved native-bundle inference, local HF/vLLM calibration, checkpointed `decision.observe`, and AnyJev distillation `decision.distill.pipeline`, `export_cases`, `synth`, `label`, `extract`, `extract_gold`, `fit`, and `soft`; RRSI candidate selection with score/noise/cost/domain gates; and a deterministic diff pre-screen. `pipeline` composes local train/test DatasetDict export, synthetic generation, teacher labeling, teacher/student gold and student synthetic feature extraction, and CPU fit/soft replay from a single versioned request. It requires separate absolute dataset, staging, and cache roots, exact local model checkpoint pins, and identical dataset fingerprints across the train/test export. Defaults are 300 gold examples per question, synthetic budgets `[300,1200]`, 1,000 bootstrap resamples, seed 0, and 1,200 synthetic states per workflow. `export_cases` requires the optional `typed-data` extra and a caller-materialized local Hugging Face `DatasetDict` containing a `train` or `test` split. It uses `load_from_disk` only: no Hub identifier, download, or remote dataset loading is accepted. Train exports produce distinct workflow exemplars and per-question labeled train cases; test exports produce per-question state/`gold_index` files, each bounded to 5,000 examples. Synthetic generation reads versioned exemplar JSON under `source_root`, requires a checkpoint-pinned local HF backend, and atomically creates versioned workflow-state JSON under `cache_root`; defaults are 1,200 states per workflow, batch size 16, max-new-tokens 700, temperature 1.0, top-p 0.95, and seed 0. Label/extract/extract-gold require a local HF checkpoint path and its SHA-256 fingerprint, forbid remote backends, and atomically create hashed-path NPZ caches under an explicit existing `cache_root`; their source JSON is read under explicit `data_root`. Gold caches contain fit-compatible `H` `[N,1,d]`, `y`, `K`, and `layers` arrays and use seeded random listings for unordered training questions with canonical test listings. Responses omit states, local paths, and raw features/probabilities. Fit/soft are cache-read-only CPU calculations. All distillation results require human review and are cutover-ineligible; no real local dataset snapshot, checkpoint run, or held-out benchmark parity has been verified. Batch inference and observation updates accept at most 128 states and 256 KiB of encoded new state data. Observation updates accept a caller-persisted checkpoint, preserve AnyJev's `fit_at`/`refit_factor` lifecycle and head-fitting options, and return the updated checkpoint because the Python process has no durable state. Checkpoints are capped at 8 MiB/4096 states and credential-scanned. The Go CLI persists these checkpoints in private local SQLite using compare-and-swap revisions and atomically stores any fitted L2 head as a review-only candidate; Python itself has no SQLite dependency or store access. The screen applies RRSI's generic credential denylist plus caller-supplied bounded literal rules; until domain inventories, executable adapters, and independent acceptance evidence are complete, a clean scan returns `incomplete`, never `pass`, and `action_ready` is always false. The JSON-lines request bound is 18 MiB to support bounded L2 heads; calibration and decision state payloads remain separately bounded. Held-out dataset execution and human approval remain workflow responsibilities; selection alone never approves or publishes a candidate.

Distillation receipts may include hash-keyed paths relative to the caller-selected staging/cache roots; they never include absolute local paths, raw states, labels, or feature vectors.

The `decision.bundle.validate` operation checks a native AnyJev `Decider.export_artifacts()` object by loading its L1/L2 payloads and adaptation arrays through the vendored library. Labeled observations require the explicit `include_observations: true` parameter; the whole bundle is credential-scanned and capped at 16 MiB. The result omits bundle contents and never authorizes use. `decision.bundle.decide` and `decision.bundle.decide_batch` receive an active bundle selected by the Go CLI, validate the payload again, and rely on upstream `Decider.load_artifacts()` to bind it to the backend name before producing advisory decisions. They have no store access and all authorization/environment-verification flags remain false. Batch operation retains the 128-state/256 KiB bound.

`decision.observe` advances AnyJev's observation/refit schedule from a versioned checkpoint supplied by the caller. New examples are bounded to 128 and 256 KiB per request; checkpoint state is capped at 4096 observations and 8 MiB. Model, question layout, fit schedule, and fit options are bound to the checkpoint. The returned checkpoint contains accumulated labeled examples and must stay in private local storage; the Python operation does not persist data or activate the resulting L2 head. The Go CLI/store supplies the durable compare-and-swap boundary; its output omits checkpoint contents and raw labeled states. Contract schemas: `schema/decision-observe-request-v1.schema.json` and `schema/decision-observe-result-v1.schema.json`; CLI contracts are documented in `docs/decisions.md`.

The `threadforge evolution select` CLI validates credential-free request JSON before invoking the Python selection operation and returns an advisory, versioned result. Selection never applies edits, approves a candidate, or authorizes execution.

Go can import/export per-question L1/L2 payloads and persist/review/export complete `Decider.export_artifacts()` bundles, including adaptation statistics and explicitly opted-in labeled observations. Approved bundles can be used for advisory inference through the versioned bridge; exact model-file fingerprint verification, full backend parity, and benchmark parity remain incomplete.

Upstream snapshots and license notices are tracked in `../THIRD_PARTY.md` and the adjacent license files.
