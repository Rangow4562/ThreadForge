# Vendored upstream modifications

This file records Threadforge changes to vendored source. Original Apache-2.0 headers and the `LICENSE.anyjev` / `LICENSE.rrsi` notices remain intact.

## AnyJev

- Source: `python/anyjev/decider.py`, based on AnyJev commit `a59a69eaa91e62dc9b42924f8491f76d1b1972ea`.
- Change: `Decider.export_artifacts(include_observations=True)` now serializes each observed typed question's `scale`, `ordered`, and `centers`; `Decider.load_artifacts()` restores these fields and rejects an observation whose reconstructed stable question key differs from the stored key.
- Rationale: score-question keys include scale and optional centers. Omitting those fields made a persisted `observe()` checkpoint ambiguous and could restore labeled examples under a different layout. The additive fields preserve typed-question identity across process restarts; older checkpoints without them retain the old defaults and fail closed when those defaults do not match the saved key.
- Coverage: `python/tests/test_protocol.py` exercises native export/load validation and checkpoint continuation for choice and score question layouts.
- Source: `python/anyjev/backends/vllm.py`, originally vendored from AnyJev commit `a59a69eaa91e62dc9b42924f8491f76d1b1972ea`; the L2 pooling behavior follows the Apache-2.0 implementation and contract in current AnyJev commit `795a4970b47218b7c0686cd579d691fc2cf8df2f`.
- Change: `VLLMBackend` now exposes `n_layers` from the tokenizer/config source (not a served-model alias) and `hidden_states()` through OpenAI-compatible `/v1/embeddings`. The backend returns final-layer `[N,1,d]` float32 vectors for AnyJev L2 heads and explicitly rejects non-final layer requests, token-logit requests, and per-position feature requests. Invalid/empty/non-finite embeddings and inconsistent vector sizes are rejected.
- Rationale: current AnyJev adds L2 heads over a vLLM pooling server; preserving the original model's absolute final-layer index avoids accepting an artifact at an unrelated server-local layer number. The vLLM service remains operator-managed and remote inference stays disabled unless the existing explicit consent contract is met.
- Coverage: `python/tests/test_vllm_backend.py` uses a loopback fixture server and stub Transformers config/tokenizer to verify the embeddings endpoint, served alias vs tokenizer/config source, layer compatibility, output shape/type, bearer header, and safe refusal paths. No live vLLM server/model was started.
- Source: `python/anyjev/decider.py`, based on AnyJev commit `a59a69eaa91e62dc9b42924f8491f76d1b1972ea`.
- Change: `Decider.fit_head()` detects the additive backend capability `final_layer_only`; when `layers` is omitted, it fits only at `backend.n_layers` instead of requesting unavailable intermediate vectors. Multi-layer candidate selection for local HF remains unchanged. The L2 backend error now describes the required capability rather than incorrectly requiring local Transformers specifically.
- Rationale: Threadforge's `decision.calibrate` protocol calls `Decider.calibrate()` without exposing an internal layer override. This default lets the versioned JSON-stdio L2 calibration path use current AnyJev vLLM pooling safely and avoids pretending the pooled final vector is an intermediate activation.
- Coverage: the integration test in `python/tests/test_vllm_backend.py` calibrates an L2 head without an explicit layer list and runs decisions through a local mock embeddings server; the resulting artifact is pinned to the actual final block count.
- Source: `python/anyjev/backends/hf.py`, originally vendored from AnyJev commit `a59a69eaa91e62dc9b42924f8491f76d1b1972ea`; the Transformers 5 API changes follow current AnyJev commit `795a4970b47218b7c0686cd579d691fc2cf8df2f` (Apache-2.0).
- Change: `python/anyjev/transformers_compat.py` selects `torch_dtype` for Transformers 4 and `dtype` for Transformers 5+ in both HF model loading and local checkpoint truncation. `HFBackend` builds causal-mask arguments from each builder's declared signature, mapping `input_embeds`/`inputs_embeds` and supplying `cache_position` only when supported; unknown signatures fail rather than guessing.
- Rationale: the optional dependency permits Transformers 4.53 and later, but the upstream 4-to-5 API rename otherwise breaks normal HF loading and depth-limited hidden-state extraction. Truncation and inference must use the same version-appropriate model-loading keyword.
- Coverage: `python/tests/test_transformers_compat.py` covers v4/v5 loading keywords, v4/v5 causal-mask signatures, and unsupported signatures; `python/tests/test_model_truncation.py` exercises the Transformers 5 dtype path. These are API-fixture tests, not a real Transformers 5 model run.
- Source: current AnyJev `anyjev/truncate.py` at commit `e79c197` (Apache-2.0 behavior reference).
- Change: `python/anyjev/truncate.py` adapts the ordinary HF checkpoint conversion behind `threadforge.anyjev-truncate-request.v1` / `decision.model.truncate`. It accepts only materialized local model/tokenizer roots, rejects linked paths and overlapping/existing output locations, uses `local_files_only=True` and `trust_remote_code=False`, stages beside a new destination, fingerprints inputs before/after conversion, removes source-path metadata, and returns only SHA-256/count/trust receipts. `dtype` defaults to `auto`; allowed explicit conversions are float16, bfloat16, and float32. Overwrite and remote model-ID behavior are intentionally not exposed.
- Rationale: make the current AnyJev checkpoint-depth capability available without implicit Hub downloads, arbitrary remote code, accidental user-data replacement, or path leakage. Conversion produces an ordinary HF checkpoint but is not evidence that a truncated head preserves accuracy or improves latency.
- Coverage: `python/tests/test_model_truncation.py` covers zero-based layer selection, tensor filtering, path-free metadata, local-only inputs, no-overwrite behavior, source mutation detection/staging cleanup, and the versioned protocol/capability receipt. The real HF-weight conversion path remains unexecuted unless optional runtime tests are available.

## RRSI

- Source: `python/rrsi/evaluate.py`, based on RRSI commit `be50316e1db05914068a973f322770ef08ed7ba1`.
- Change: `TaskResult` now rejects non-finite/out-of-range rewards, nonpositive weights, misaligned reward/weight/token arrays, invalid missing counts, and invalid token values. `aggregate()` requires a positive integer `k`, at least one task, and exactly `k` result rows per task, then revalidates mutable task records before folding them. `EvalResult.from_json()` recomputes and checks expected/missing counts, weighted score, and token mean before accepting persisted evaluation history; `to_json()` performs the same consistency check before writing.
- Rationale: the upstream scorer used `zip()` over task arrays, silently truncating mismatched rewards and weights; persisted aggregate summaries could also disagree with per-task trial rows. Strict checks keep missing trials represented by explicit zero-reward rows and prevent inconsistent metrics from entering later calibration/selection.
- Coverage: `python/tests/test_rrsi_evaluate.py` covers valid weighted/missing trials, vector-length mismatches, non-finite and out-of-range values, invalid missing/token counts, mutated task rows, wrong `k`, empty task sets, and persisted summary tampering.
- Source: `python/rrsi/config.py`, `python/rrsi/evaluate.py`, and `python/rrsi/loop.py`, based on RRSI commit `be50316e1db05914068a973f322770ef08ed7ba1`.
- Change: benchmark execution requires strict boolean `benchmark_execution_opt_in=true`; it defaults false and is checked before baseline, held-out, round, re-evaluation, candidate drafting/evaluation, `Domain.run()`, and domain smoke paths. The loop passes the configured value explicitly and refuses before analysis/model calls or Git/evaluation mutations.
- Rationale: domain smoke checks can launch Docker or billable model calls just like full runs. Guarding only `Domain.run()` left a path for a normal evolution round to execute smoke before the evaluator's opt-in check. All orchestrated benchmark paths now share the same fail-closed consent check.
- Coverage: `python/tests/test_rrsi_evaluate.py` verifies default denial without domain, Git, candidate, or smoke side effects; explicit opt-in behavior; strict boolean validation; and config loading.
- Source: `python/rrsi/llm.py`, `python/rrsi/loop.py`, `python/rrsi/analyst.py`, `python/rrsi/propose.py`, `python/rrsi/critic.py`, and `python/rrsi/digester.py`, based on RRSI commit `be50316e1db05914068a973f322770ef08ed7ba1`.
- Change: role inference defaults to the shared offline-only Hugging Face helper, configured by `RRSI_LOCAL_MODEL_PATH` and optional device/dtype variables. The helper's local-file, no-remote-code, input, and output limits apply. Vertex requires strict boolean `remote_inference_opt_in=true` before client construction. The loop threads this setting through analyst, digester, proposer, critic, and repair calls.
- Rationale: the upstream default instantiated a remote Vertex model. Threadforge uses a configured local checkpoint first and fails without a remote fallback when it is missing; a remote provider remains an explicit operator choice.
- Coverage: `python/tests/test_rrsi_llm.py` verifies local default routing, no fallback when the local model is missing, strict boolean validation, missing Vertex configuration, and the opt-in request path with a mocked client only.
- Style-only changes in `python/rrsi/components.py`, `python/rrsi/digester.py`, and `python/rrsi/loop.py` rename ambiguous `l` loop variables so the vendored module passes Ruff E741; behavior is unchanged.
- Source: `rrsi/domains/eng/adapter.py`, RRSI commit `be50316e1db05914068a973f322770ef08ed7ba1`.
- Change: the inventory-aware Threadforge domain rule set v3 ports the upstream EngDesign task-ID namespace as `engineering-design-task-id` and restores the `engdesign_bench` alias under `pristine-benchmark-tree`; legacy screen v1 keeps its rule set unchanged. V2 schemas/repair-history readers accept both rule-set v2 and v3 so previously recorded v2 evidence remains readable.
- Rationale: the upstream EngDesign critic rejects hard-coded task IDs and direct references to the pristine benchmark tree before evaluation. These signals are deterministic screens only; they do not imply complete inventory coverage or benchmark acceptance.
- Coverage: `python/tests/test_protocol.py` exercises every one of the 19 pinned static domain patterns, verifies v1 non-regression, v2 task-ID blocking, redaction of the matched ID, and the v3 rule-set marker; Go repair validation retains read compatibility for v2 history.
- Source: `python/threadforge_domains/coding/adapter.py`, `python/threadforge_domains/coding/briefs.py`, `python/threadforge_domains/coding/render.py`, `python/threadforge_domains/coding/rrsi.json`, `domains/coding/`, and `third_party/harbor_terminus2/`, based on RRSI commit `be50316e1db05914068a973f322770ef08ed7ba1`.
- Change: the coding adapter loads the pinned Terminal-Bench/SWE-bench evolve/held-out sets only from a private `threadforge.rrsi-domain-inventory-bundle.v1`; routes both Harbor datasets through the RRSI `Domain` interface; requires a configured Harbor environment; defaults model calls to a loopback OpenAI-compatible endpoint; and requires `remote_inference_opt_in=true` plus an explicit model for remote inference. Existing partial Harbor jobs are preserved and refused rather than renamed or overwritten. The copied Harbor agent fork retains its Apache license and original notices; benchmark data and the Harbor CLI are not included.
- Rationale: implement the coding domain without checking task IDs into Threadforge, silently selecting a paid provider, or destroying incomplete local run artifacts.
- Coverage: `python/tests/test_rrsi_domains.py` covers private split loading, dataset routing, model-provider consent, local credential stripping, scoring, and preservation of an incomplete local job; tests perform no Harbor run, Docker task, or model invocation.

## RRSI EngDesign domain adapter

- Source: `rrsi/domains/eng/adapter.py`, `rrsi/domains/eng/rrsi.json`, and `rrsi/third_party/archipelago/harness_eng/`, RRSI commit `be50316e1db05914068a973f322770ef08ed7ba1`. The seven `harness_eng` source files in `third_party/archipelago/` were SHA-256 compared with the pinned clean checkout and matched byte-for-byte; the shared Archipelago Apache-2.0 license and all file headers remain in place.
- Change: `python/threadforge_domains/engineering/adapter.py` loads the private verified EngDesign-Open/EngDesign-v1 bundle, exposes v1 only through explicit `surface_ids("engdesign-v1")`, validates task IDs and bounded local trial artifacts, calculates binary pass/continuous score/valid/no-submission/token aggregates, applies the upstream 0.03 validity-drop and 0.02 no-submission-rise guards, and renders trace data as untrusted. Reads reject linked/reparse path components and changing/oversized files; records passed to analysis are allowlisted metrics, and credential-bearing trajectories are withheld. Because v1 reuses the same 61 IDs, `heldout_ids()` deliberately returns an empty list. New `python/threadforge_domains/engineering/runtime.py` verifies an external `threadforge.engineering-runtime-pin.v1`: fixed RRSI revision, clean evaluator Git revision, benchmark/evaluator tree digests, exact task-set digest, immutable image reference, operator-recorded license IDs/review ID, and the generated manifest's agent-visible file allowlist. The pin is local integrity evidence only, not a signature or acceptance claim. With explicit benchmark opt-in, `run()` now verifies the pin and candidate fingerprint, stages read-only task/harness inputs, invokes the interactive offline container runner, brokers model completions through the host bridge, starts the task-local MCP gateway, runs the canonical evaluator in a separate offline container, and writes resume-safe trial artifacts with metadata committed last. `smoke()` exercises this one-trial path. The consent settings in `python/threadforge_domains/engineering/rrsi.json` default false. Mocked tests cover orchestration and transport; no real Docker/image/model/evaluator/benchmark execution is acceptance evidence. The locked, digest-pinned linux/amd64 image recipe is in `containers/engineering/`, but no image has been built or validated with a live Docker engine here.
- Gateway: `python/threadforge_domains/engineering/gateway.py` registers the seven legacy-compatible file/PDF/shell tool names with read/write annotations. File reads and searches are bounded and paginated, writes are restricted to the active task `output/`, PDF parsing calls only `run_sandboxed`, and shell execution requires `THREADFORGE_ACTIVE_WORKSPACE`, `THREADFORGE_ENGINEERING_BENCHMARK_ROOT`, `THREADFORGE_ENGINEERING_EVALUATOR_ROOT`, and preloaded digest-pinned `THREADFORGE_ENGINEERING_EXECUTION_IMAGE`. The ASGI origin guard permits only loopback Host/Origin values; Uvicorn binds only to `127.0.0.1`. The optional `[workspace]` extra declares FastMCP `>=2.3.2` and Uvicorn.
- Rationale: make the verified Engineering surface usable for local RRSI inventory/scoring workflows without mislabeling the same IDs as an independent holdout, trusting unverified result JSON, or executing an unauthenticated benchmark checkout.
- Coverage: `python/tests/test_engineering_domain.py` checks explicit surfaces, opt-in and runtime refusal before writes, missing-trial denominator handling, result integrity, guards, and trace rendering. `python/tests/test_engineering_runtime.py` exercises the pin verifier with temporary task/evaluator fixtures, including clean Git revision, changed bytes, task-set mismatch, candidate/run root separation, and evaluator visibility expansion. `python/tests/test_engineering_security.py` covers the container boundary. `python/tests/test_engineering_gateway.py` checks pagination, task/output scoping, Host/Origin rejection, tool metadata, and mocked FastMCP app setup. FastMCP/Uvicorn are not installed in the current environment and an isolated package install could not reach the package index, so the actual HTTP server was not started. No benchmark data, evaluator, image, or result fixture is acceptance evidence; no real Docker or benchmark execution was run.

## RRSI Harvey LAB workspace adapter

- Source: RRSI commit `be50316e1db05914068a973f322770ef08ed7ba1`, including `domains/workspace/adapter.py`, `briefs.py`, `render.py`, `workspace_driver.py`, `workspace_judge.py`, `mcp_gateway/gateway.py`, and `produce.sh`; consent changes also touch `python/rrsi/config.py`, `domain.py`, `loop.py`, and `modelpolicy.py`.
- Vendored engine: the 35-file `third_party/archipelago/` subtree was copied byte-identically from the pinned RRSI source, retaining its Apache-2.0 `LICENSE` and all original file notices. No Harvey tasks, split IDs, benchmark results, credentials, or Python dependency sources were copied.
- Change: `WorkspaceDomain` loads only `rrsi-agentic-workspace` evolve/held-out IDs from the private verified inventory bundle, rejects mixed splits, validates weighted rubric results and token evidence, and preserves partial jobs. `RRSIConfig` now strictly validates three consent booleans, each default false: `benchmark_execution_opt_in`, `remote_inference_opt_in`, and `remote_evaluation_opt_in`; `rrsi.loop.Run` propagates all three to the loaded Domain. Policy inference remains loopback-local by default; remote policy routing still requires `remote_inference_opt_in` and a configured remote model. The official Vertex rubric judge requires the separate remote-evaluation opt-in and project configuration before any run artifacts are created.
- Runner hardening: each task receives an isolated loopback MCP gateway with direct reads scoped to its workspace, writes restricted to `output/`, and web search removed. Shell/Python execution requires an already-installed image pinned by `sha256`; Docker runs with no network, read-only task documents, writable task output only, dropped capabilities, resource bounds, and no inherited credentials. Existing partial task workspaces/results are preserved rather than recursively deleted or overwritten. Harvey checkouts must match the pinned commit and have a clean task tree.
- Rationale: make the domain executable from Threadforge without relying on the legacy RRSI checkout, while retaining local-first policy inference, independent consent for remote judging, and a bounded filesystem/process boundary for untrusted task code.
- Packaging: the setuptools `build_py` command includes `domains/workspace/` and `third_party/archipelago/` as package runtime assets, plus `CREDITS.anyjev.md` and this upstream-modification audit; the `sdist` command temporarily stages those assets under `threadforge_domains/workspace/runtime/` and cleans up after archive creation. The adapter prefers source-tree assets and falls back to package runtime assets. Harvey tasks, IDs, results, credentials, and Python dependencies are not copied.
- Coverage: `python/tests/test_rrsi_domains.py` covers verified split use, mixed-split rejection, remote-judge refusal before writes, loopback model env, packaged-runtime fallback, score reconciliation, malformed-score rejection, exact-manifest job completion, and partial-job preservation. `python/tests/test_workspace_security.py` covers path confinement, symlink escape rejection, secret filtering, and immutable image pins. Focused validation: 46 original workspace/security tests passed; updated runtime tests pass; wheel install fallback and sdist-to-wheel builds pass. No Harvey task, Vertex judge, Docker container, local model, or held-out benchmark was run; adapter and release acceptance remain unverified.
